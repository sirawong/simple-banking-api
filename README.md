# Simple Banking API

A production-ready RESTful banking API built with Go, featuring account management, deposits, withdrawals, and transfers with full ACID compliance via PostgreSQL transactions.

## Tech Stack

| Layer | Technology |
|-------|-----------|
| Framework | [Gin](https://github.com/gin-gonic/gin) |
| ORM | [GORM](https://gorm.io) + PostgreSQL driver |
| Cache | [Redis](https://github.com/redis/go-redis) |
| DI | [Wire](https://github.com/google/wire) |
| Config | [Viper](https://github.com/spf13/viper) |
| Logging | [Zap](https://go.uber.org/zap) |
| Docs | [Swaggo](https://github.com/swaggo/swag) |
| Testing | [Testify](https://github.com/stretchr/testify) + [Mockery](https://github.com/vektra/mockery) |

## Getting Started

### Prerequisites

- Go 1.22+
- Docker & Docker Compose
- `wire` CLI: `go install github.com/google/wire/cmd/wire@latest`
- `swag` CLI: `go install github.com/swaggo/swag/cmd/swag@latest`
- `mockery` CLI: `go install github.com/vektra/mockery/v2@latest`
- `golangci-lint`: https://golangci-lint.run/usage/install/

### Local Development

```bash
# 1. Copy env file
cp .env.example .env

# 2. Start infrastructure
make docker-up

# 3. Install dependencies
make tidy

# 4. Generate code (wire DI, mocks, swagger)
make gen

# 5. Run database migrations
make migrate

# 6. Start the server
make run
```

The API will be available at `http://localhost:8080`.

Swagger UI: `http://localhost:8080/swagger/index.html`

### Docker (full stack)

```bash
make docker-up
make docker-logs
```

## API Reference

### Accounts

| Method | Path | Description |
|--------|------|-------------|
| POST | `/api/v1/accounts` | Create a new account |
| GET | `/api/v1/accounts/:id` | Get account balance |
| GET | `/api/v1/accounts/:id/transactions` | List transactions (paginated) |

### Transactions

| Method | Path | Description |
|--------|------|-------------|
| POST | `/api/v1/transactions/deposit` | Deposit funds |
| POST | `/api/v1/transactions/withdraw` | Withdraw funds |
| POST | `/api/v1/transactions/transfer` | Transfer between accounts |

### Response Format

All endpoints return a unified envelope:

```json
{
  "success": true,
  "data": { ... }
}
```

Error response:

```json
{
  "success": false,
  "error": "insufficient balance"
}
```

### Example Requests

**Create Account**
```bash
curl -X POST http://localhost:8080/api/v1/accounts \
  -H "Content-Type: application/json" \
  -d '{"user_id": "<uuid>", "currency": "THB"}'
```

**Deposit**
```bash
curl -X POST http://localhost:8080/api/v1/transactions/deposit \
  -H "Content-Type: application/json" \
  -d '{"account_id": "<uuid>", "amount": "1000.00"}'
```

**Transfer**
```bash
curl -X POST http://localhost:8080/api/v1/transactions/transfer \
  -H "Content-Type: application/json" \
  -d '{"from_account_id": "<uuid>", "to_account_id": "<uuid>", "amount": "250.00"}'
```

## Design Decisions

### Decimal arithmetic for money
All monetary values use `github.com/shopspring/decimal` and are stored as `DECIMAL(20,2)` in PostgreSQL. This avoids floating-point precision errors (e.g. `0.1 + 0.2 != 0.3` in IEEE 754).

### Pessimistic locking for transfers
`FindByIDForUpdate` acquires a `SELECT ... FOR UPDATE` row-level lock inside a database transaction, preventing race conditions when two concurrent transfers touch the same accounts.

### Redis balance cache
Account balances are cached in Redis with a 60-second TTL and invalidated immediately on any mutating operation (deposit, withdraw, transfer). This reduces DB reads for frequent balance checks.

### Wire DI
Dependency injection is wired at compile time using Google Wire. `internal/di/di_gen.go` is generated by `scripts/gen_wire.sh` which scans provider annotations. `cmd/api/di/wire_gen.go` is generated by the `wire` CLI.

## Testing

```bash
# Unit tests
make test

# With coverage report
make test-cover
```

Unit tests use in-process mocks (via `testify/mock`) for all repository and cache dependencies. Tests that exercise DB transactions (Deposit, Withdraw, Transfer happy paths) require an integration/test database.
